## 2. Első igazolt hiba: zárolt teszt időkorlátja módosítható

Javítandó

A `trg_lock_quiz_header_update` csak három mezőt véd:

```
BEFORE UPDATE OF title, subject_id, subject_grade ON quizzes
```

A `default_time_limit_min` kimaradt.

A próbámban ezt a műveletet az adatbázis engedélyezte, pedig a teszt már zárolt volt:

```
UPDATE quizzes
SET default_time_limit_min = 99
WHERE id = 1;
```

Ez azt jelenti, hogy a zárolt teszt egyik beállítása utólag módosítható.&#x20;

## 3. Második igazolt hiba: a lezárt dolgozat újranyitható, majd törölhető

Kritikus

Ez a fontosabb probléma.

A `sessions` tábla CHECK megszorítása biztosítja, hogy az `ACTIVE` állapothoz `ended_at IS NULL`, a `FINISHED` állapothoz pedig nem NULL lezárási idő tartozzon.

De nem tiltja a `FINISHED` → `ACTIVE` visszaállítást.

A következő műveletsort teszteltem:

```
-- 1. A dolgozat lezárása
UPDATE sessions
SET status = 'FINISHED',
    ended_at = '2026-11-07T14:00:00.000Z'
WHERE id = 1;

-- 2. A lezárt dolgozat újranyitása
UPDATE sessions
SET status = 'ACTIVE',
    ended_at = NULL
WHERE id = 1;

-- 3. A résztvevő törlése
DELETE FROM participants WHERE id = 1;
```

SQLite-próba eredménye

Védelem megkerülhető

| Dolgozat lezárása    | &#x20;Sikeres             |
| -------------------- | ------------------------- |
| Dolgozat újranyitása | &#x20;Sikeres             |
| Résztvevő törlése    | &#x20;Sikeres             |
| Kapcsolódó válaszok  | Törlődtek a CASCADE miatt |

Tehát a jelenlegi adatbázisban a „lezárt dolgozat soha nem törölhető” szabály még nem teljesül.&#x20;

Javasolt megoldás: vezessünk be egy állapotátmenetet védő triggert:

```
CREATE TRIGGER IF NOT EXISTS trg_prevent_session_reopen
BEFORE UPDATE OF status ON sessions
WHEN OLD.status = 'FINISHED'
     AND NEW.status IS NOT OLD.status
BEGIN
    SELECT RAISE(
        ABORT,
        'Lezárt dolgozat nem nyitható újra!'
    );
END;
```

Ezzel az igazolt törlési kiskapu megszűnik. Az `ended_at` utólagos átírását is érdemes tiltani.

## 5. Mit javaslok most?

Nem vezetnék be új táblákat vagy új funkciókat. A meglévő adatbázis védelmének befejezésére koncentrálnék, ebben a sorrendben:

1. Lezárt session visszanyitásának tiltása – ez bizonyított adatvesztési kiskaput zár.
2. Zárolt teszt teljes UPDATE-védelme – ne maradjon ki beállítás.
3. Lezárt sessionök és résztvevők történeti adatainak védelme – az eredményeket meghatározó adatok maradjanak változatlanok.
4. Válaszrekordok módosítható mezőinek pontosítása – a tanári felülbírálás működjön, az eredeti válasz és eredményeinek alapadatai ne változhassanak meg.
5. Automatizált integritási próbák – a tiltott és a megengedett műveleteket egyaránt tesztelni kell.
